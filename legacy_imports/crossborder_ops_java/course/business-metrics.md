# 经营指标口径

本文档只描述当前代码已经实现的口径，不补充复杂财务规则。

## 销售额

- 业务含义：订单原始成交金额。
- 计算公式：当前经营概览不直接汇总销售额字段；演示数据中对应 `cb_order.gross_amount`。
- 使用的数据表或字段：`cb_order.gross_amount`。
- 排除条件：当前经营概览没有使用该字段做汇总。
- 边界情况：如果后续要展示销售额，应明确它与净销售额的区别。

## 净销售额

- 业务含义：扣除平台侧基础调整后的订单收入，是当前经营概览的核心收入指标。
- 计算公式：`SUM(cb_order.net_amount)`。
- 使用的数据表或字段：`cb_order.net_amount`，按 `store_id` 和 `order_date` 过滤。
- 排除条件：当前查询没有按 `status` 排除取消订单，演示数据里的订单均为 `COMPLETED`。
- 边界情况：无订单时返回 0；多店铺查询会直接相加，不做币种换算。

## 利润

- 业务含义：订单层面的毛利润。
- 计算公式：`SUM(cb_order.profit_amount)`。
- 使用的数据表或字段：`cb_order.profit_amount`。
- 排除条件：当前实现不额外扣除退款、广告费或物流费。
- 边界情况：无订单时返回 0。

## 利润率

- 业务含义：毛利润占净销售额的比例。
- 计算公式：`利润 / 净销售额 * 100%`。
- 使用的数据表或字段：由 `profit_amount` 和 `net_amount` 汇总计算。
- 排除条件：同利润口径，不扣除退款、广告费或物流费。
- 边界情况：净销售额为 0 时返回 0。

## 平均订单利润

- 业务含义：每个有效订单平均贡献的毛利润。
- 计算公式：`利润 / 有效订单数`，保留 2 位小数。
- 使用的数据表或字段：`cb_order.profit_amount` 和订单行数。
- 排除条件：当前没有按订单状态过滤；演示数据订单均为 `COMPLETED`。
- 边界情况：有效订单数为 0 时返回 0。

## 退款金额

- 业务含义：指定时间范围内发生的退款总额。
- 计算公式：`SUM(cb_refund.refund_amount)`。
- 使用的数据表或字段：`cb_refund.refund_amount`，按 `store_id` 和 `refund_date` 过滤。
- 排除条件：当前不按退款原因或处理状态过滤。
- 边界情况：无退款记录时返回 0。

## 退款率

- 业务含义：退款金额相对净销售额的比例。
- 计算公式：`退款金额 / 净销售额 * 100%`。
- 使用的数据表或字段：`cb_refund.refund_amount` 和 `cb_order.net_amount`。
- 排除条件：当前不从利润或净销售额中反向扣减退款，只作为独立风险指标展示。
- 边界情况：净销售额为 0 时返回 0。

## ACOS

- 业务含义：广告花费占广告销售额的比例，用于判断投放成本压力。
- 计算公式：`SUM(cb_ad_daily_report.spend) / SUM(cb_ad_daily_report.sales_amount) * 100%`。
- 使用的数据表或字段：`cb_ad_daily_report.spend`、`sales_amount`。
- 排除条件：当前不区分广告归因窗口，也不扣除自然销售。
- 边界情况：广告销售额为 0 时返回 0。

## ROAS

- 业务含义：每 1 元广告花费带来的广告销售额。
- 计算公式：`SUM(sales_amount) / SUM(spend)`。
- 使用的数据表或字段：`cb_ad_daily_report.sales_amount`、`spend`。
- 排除条件：当前不区分广告归因窗口。
- 边界情况：当前代码用 `spend.max(1)` 避免除零；花费为 0 时不会抛出异常，但业务解释应谨慎。

## 有效订单数

- 业务含义：参与经营概览计算的订单行数。
- 计算公式：`COUNT(cb_order.id)`。
- 使用的数据表或字段：`cb_order.id`。
- 排除条件：当前没有在查询中按 `status` 过滤；演示数据均为 `COMPLETED`。
- 边界情况：无订单时为 0。

## 时间范围

- 业务含义：工具调用时用于过滤订单、退款、广告或评论的日期范围。
- 计算公式：显式传入 `startDate/endDate` 时使用传入日期；为空时由 Tool 使用默认最近 30/60 天或最近 N 个月。
- 使用的数据表或字段：`order_date`、`refund_date`、`report_date`、`review_date`。
- 排除条件：没有时区换算逻辑，使用服务端本地日期。
- 边界情况：日期格式必须是 `yyyy-MM-dd`。

## 多店铺口径

- 业务含义：运营总监可看全部店铺，店长/运营只能看自己的店铺范围。
- 计算公式：`storeName` 为空且无用户范围时汇总全部店铺；有店铺范围时按 `store_id` 过滤。
- 使用的数据表或字段：各业务表的 `store_id`。
- 排除条件：课堂默认 `app.auth.enabled=false` 时后端不强制鉴权，通常按全部店铺演示。
- 边界情况：多店铺汇总直接相加，不做币种换算。

## 币种处理

- 业务含义：店铺表记录币种，订单金额使用该店铺币种。
- 计算公式：当前没有汇率换算。
- 使用的数据表或字段：`cb_store.currency` 仅用于说明店铺币种，指标计算未使用该字段。
- 排除条件：跨 USD、GBP、EUR 店铺汇总时不会转换为统一币种。
- 边界情况：课堂讲解多店铺汇总时，应说明这是演示口径。

## 空数据处理

- 业务含义：查询范围内没有数据时，系统应返回可理解的空结果。
- 计算公式：金额类返回 0，列表类返回空列表，图表工具在无趋势数据时返回提示文本。
- 使用的数据表或字段：所有业务表。
- 排除条件：当前没有统一的空数据 DTO。
- 边界情况：前端只有收到 `VISUAL_PAYLOAD:` 时才渲染图表，否则按普通文本展示。
